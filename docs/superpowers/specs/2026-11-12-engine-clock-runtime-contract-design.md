## Approaches and chosen proposal

| Approach | Benefit | Limitation / decision |
| --- | --- | --- |
| Keep bare hosted runtime and full ImageVersion equality | Existing fail-closed semantics, no new image route | Cannot request a particular reported ImageVersion through the existing OS label; preserve for old studies, not the proposed solution |
| Immutable self-hosted VM snapshot | Can control more of host image/kernel/CPU eligibility | No configured/authorized runner fleet or snapshot identity exists; do not provision one in this task |
| Sealed container userspace with authenticated image archive and strict host profile | Reuses exactly the same userspace bytes without registry publication; independently measures remaining host dependencies | Selected by root for a future protocol; still shares host kernel/CPU and may reject mismatched hosts |

The selected transport is an authenticated Actions artifact containing a Docker-save archive. Pin the archive SHA256, Docker image config digest and ordered rootfs diffIDs. Do not call an archive/config digest an OCI registry manifest digest. No registry publication is required. If a registry route is considered later, it needs a different explicit distribution schema and a genuine platform-specific manifest digest; mutable tags or a multi-platform index alone are insufficient.

This changes the identity definition only in a separately registered future protocol. It must never project/filter an old record to pass the consumed validator. Outer ImageVersion remains visible in future provenance; a difference could be admitted only when the new inner identity and strict host profile match. Without sealed-image proof, no fallback to version strings or ignoring ImageVersion is permitted.

## Assurance boundaries

1. **Installed content identity:** authenticated image archive, image config/rootfs descriptors, closed installed-file inventory and separately Git-bound application source. This is the assurance the proposal can test before a provider constructor.
2. **Execution profile equality:** observed kernel, CPU eligibility, Docker/runtime versions and nonsecret render/import/mount configuration. These are source-bound observations, not hardware attestation or identical physical hosts.
3. **Actual native selection:** loaded GL/driver libraries, context renderer and callback/GPU behavior are not proved by installed hashes. No GL context/probe, `ldd` execution, native import or extra readback is authorized to fill this gap. Any later native observation needs its own registration and observer budget.

Matching this contract does not prove deterministic pixels, GPU freshness, cache hits, observer neutrality, process execution from independent OS tracing or binary selection of every future lazy-loaded plugin. File hashing itself warms filesystem caches and adds CPU/I/O load; future arms must share that preflight, record its cost and not claim neutrality.

## Future records and interfaces

The inactive proposal is `docs/evidence/STAGE7_ENGINE_CLOCK_RUNTIME_CONTRACT_PROPOSAL.json`, schema `engine-clock-runtime-contract-proposal-v1`. Its null preparation/image/lock/launch values are valid only while `status=INACTIVE_DESIGN_ONLY`, `image_preparation_ready=false`, `native_admission_ready=false`, and every native/model allowance is0. The pure metadata implementation may use synthetic complete fixtures; they are never actual preparation/runtime receipts.

Future identity schema: `engine-clock-installed-identity-v1`, with exact top-level keys `schema`, `core`, `core_sha256`. Canonical hash is SHA256 of UTF-8 `json.dumps(core,sort_keys=True,separators=(',',':'),ensure_ascii=True,allow_nan=False)` with no newline. Reject duplicate JSON keys, unknown fields, NaN/infinity, wrong types, bool-as-int, null required evidence, mutable image tags, unsupported platform and cross-schema records.

`core` has exactly these objects; their nested fields are fixed below:

| Object | Required fields and semantics |
| --- | --- |
| `image` | `distribution` literal `actions-docker-save-v1`; positive `artifact_id`; `artifact_zip_sha256`, `image_tar_sha256`, `config_digest`; ordered nonempty `rootfs_diff_ids`; `platform` literal `linux/amd64`; `installed_files_sha256`; `build_recipe_sha256`; `lock_sha256`; `assets_zip_sha256` |
| `versions` | `python`, `executable`, `numpy`, `opencv_python_headless`, `cv2`, `panda3d`, `metadrive_simulator`; exact Python3.11.18/NumPy2.4.6/OpenCVheadless5.0.0.93(cv2 5.0.0)/Panda1.10.13/MetaDrive0.4.3, executable `/opt/venv/bin/python`; full Python build string recorded separately in provenance |
| `host` | `sysname`, `release`, `version`, `machine`, `byteorder`, `cpu_vendor`, `cpu_model`, `cpu_flags`, `logical_cpus`, `affinity_cpus`; exact observed strings, nonempty sorted unique nonempty string flags; positive logical/affinity counts with affinity<=logical, `Linux`/`x86_64`/`little` required |
| `engine` | `docker_client`, `docker_server`, `docker_api`, `oci_runtime`, `storage_driver`; exact nonempty observed version/name strings |
| `configuration` | `read_only_rootfs=true`, `source_mount_read_only=true`, `host_native_library_mounts=false`, `host_display_mounts=false`, `device_passthrough=false`, `imports_isolated=true`; `render_env` exactly LIBGL_ALWAYS_SOFTWARE=`1`, PYOPENGL_PLATFORM=`glx`, OMP_NUM_THREADS=`2`; `cache_policy` literal `fresh-per-case-external-bounded`; `environment_profile_sha256` binds the complete reviewed nonsecret environment allowlist, including locale and all permitted native-affecting selectors (not credential values) |

Every `*_sha256` above is64lowercase hex. `config_digest` and every diffID are `sha256:` plus64lowercase hex. `assets_zip_sha256` must equal the unchanged official MetaDrive0.4.3 asset SHA256 `4f0da9f5143a1258131c5b55f77bdf170c0f9bce8a9f18dd41b3678df779eac9`. No artifact run ID, native source HEAD, PID, UUID, nonce, wall time, host ImageVersion, absolute cache path or secret value enters core. Source C and A legitimately have different HEADs and live process IDs; those remain separately authenticated, never erased. Prepared image artifact ID and content stay fixed across future C/A.

Future preflight schema `engine-clock-runtime-preflight-v1` has exact top-level keys `schema`, `status`, `identity`, `provenance`, `inventory`, `errors`. Success status `INSTALLED_PROFILE_VALIDATED` means only the above assurance, not native admission/scientific PASS. Failure status `FAILED_OR_INCOMPLETE`, nullable identity and bounded errors preserve the stage; provider/capture/model totals stay null on pre-admission failure. Provenance holds authenticated preparation and current-run contexts, complete runtime diagnostic strings including outer ImageOS/ImageVersion/full Python build, observed sanitized mounts, CPU affinity identifiers, nonce/container IDs, timings and token/proxy/CA **presence only**. Version/config origins are host-owned observations plus in-container file checks; a container environment variable asserting an image digest is not proof.

The pure tool accepts/compares only identity records, not arbitrary preflight envelopes. It must not claim authentic API association, filesystem collection, container execution or a provider from a valid synthetic identity. Rich preflight/API/inventory integration belongs to a later collector implementation and reviewed launch adapter.

## Installed-file manifest and sealing

Future `installed-files-v1` contains exact `schema`, `roots`, `runtime_exclusions`, `entries`; roots are `/usr`, `/lib`, `/lib64`, `/opt/venv`, `/opt/python`, `/etc`, plus exact resolved canonical aliases. Inventory covers the complete installed distribution closure (not just four top-level versions), Python executable/stdlib/site-packages, Panda/CV/NumPy binaries, native loader/GL/Mesa/LLVM/Xvfb and full extracted official MetaDrive assets. Deduplicate overlapping canonical roots and include symlink descriptors rather than silently skipping aliases. The genuine prepared manifest fixes which roots exist and their closed entry set; adding/deleting/changing a file fails. `runtime_exclusions` is exactly the sorted literal list `/etc/hostname`, `/etc/hosts`, `/etc/mtab`, `/etc/resolv.conf`: these Docker-managed/virtual metadata paths are checked separately in provenance, never treated as installed binary content or used as native lookup roots. Only the expected `/etc/mtab` link to `/proc/mounts` or `/proc/self/mounts` is permitted without traversal; all other symlink escapes still reject. The file inventory is not the old producer70 snapshot.

Each entry is either `{path,kind:'file',mode,nbytes,sha256}` or `{path,kind:'symlink',target}`. Paths are absolute canonical UTF-8 names under approved roots, <=4096bytes; reject traversal, devices/FIFO/socket entries and symlink cycles/escapes. Links may cross approved roots but may not resolve into checkout/cache/tmp/auth/device paths. Expected directory/alias traversal is finite; every returned file must be represented. Inventory hashes actual bytes and modes, not package RECORD claims alone. Empty regular files are valid; per-file cap512MiB. The image identity/expected inventory is bound to an authenticated preparation artifact and Git-locked recipe/inputs, not an inventory generated and trusted solely by the same observed run.

Image rootfs is read-only, no runtime pip/apt/setup-python or mutable install overlay. Application checkout mounts read-only at `/work/repo`; the dependency image does not bake a second application copy. Imports originate only in reviewed checkout/installed roots; reject user sitecustomize/usercustomize, unregistered PYTHONPATH and loader overrides such as LD_PRELOAD/LD_LIBRARY_PATH. Required Python isolation is explicitly implemented in the future launcher, not assumed from flags alone. The launcher builds its environment from the sealed reviewed nonsecret profile and explicit credential-routing/temp/context exceptions; reject unexpected native-affecting overrides and do not silently remove a changed value to manufacture equality. Mutable output/temp/cache paths are outside library roots. Docker-managed `/proc`, `/sys`, `/dev`, hostname/hosts/resolver mounts are recorded and checked by a sanitized semantic allowlist; no host GL/DRI/X11 socket or library directory is passed through. Proxy/CA/token routing uses supplied settings and separate read-only trust paths, without overriding native lookup paths or persisting credential values. Do not dump full `docker inspect` Config.Env.

Keep existing software-route flags; do not silently set new GALLIUM_DRIVER/LP_NUM_THREADS/clock/shader/default knobs. Installed libraries and environment constrain selection but do not prove the actual chosen GL renderer before a context exists. Source/import/mount checks and read-only roots reduce mutation windows; they are not a defense against a compromised CI host.

## Preparation and provider-free preflight sequence

1. A separately reviewed provider-free implementation first creates real hash-locked base/Python/wheel/deb/asset inputs. Source-controlled lock must cover the complete dependency graph and genuine file digests. Resolve and review actual values before a build; never fill illustrative hex or claim a current image.
2. One future preparation workflow builds the dependency image without constructing/importing a native engine or invoking ORT/official model, records its actual config ID/rootfs diffIDs and closed file manifest, then saves a Docker archive. Exported artifact has exactly `image.tar`, `preparation.json`, `installed-files.json`. No registry/Cloud image publication or secret-bearing image layer. Preparation source/workflow/head/attempt/artifact API/ZIP SHA/inner member hashes must be authenticated.
3. A host preflight downloads the original image artifact with streaming size/SHA limits, verifies all three allowed members, loads the archive and independently matches Docker image ID to config digest, ordered diffIDs, architecture/OS and platform. Config/image/registry/archive hashes are not interchangeable. Do not reuse the old192MiB in-memory dataset downloader for this image transport. Reject unexplained extra image/tag/platform payloads and authenticate before invoking Docker load.
4. The host launches the reviewed future preflight command in that exact image, inspects the actual container image ID/read-only rootfs/sanitized mounts/config and binds a host receipt to current source/run/nonce. Source/API admission and expected image reference are separately bound. No `docker exec` split for the parent/child permit: a future native orchestrator and all bounded Xvfb children must live in the same PID namespace so one-use FD/ancestry/group/reaping remain meaningful.
5. In-container provider-free collector verifies installed bytes, allowed paths/import configuration and absence of installed/imported ORT; compares the exact expected identity and host profile. Unsupported observations, missing fields, timeout/size/disk errors or mismatch fail closed with original stage/error. No fallback or retries, no provider construction, render/context probe, hidden native import or model invocation.
6. Provider-free source and fixture tests plus one bounded preparation/preflight evidence review must finish before designing a separate new native protocol. Recompute all phase/child/storage budgets including parent and child hashing, API and image transport; do not inherit1320/270s unchanged. A new image/contract cannot activate the old canary or reuse its four unexecuted cases.

Proposed provider-free bounds: image.tar<=2GiB, outer ZIP<=2GiB, expanded installed content<=3GiB, inventory read<=4GiB/100000entries, manifest<=16MiB, identity<=128KiB, per-file<=512MiB, log<=1MiB, inventory<=180s and image download<=300s with1MiB chunks. Require>=16GiB genuinely free on the union of archive/Docker-data filesystems, accounting for shared filesystem capacity once. These are future caps, not measured feasibility. Any larger need requires a reviewed contract revision before preparation, not an automatic extension. No native phase/time/provider budget is granted by these resource limits.

## Equality and negative cases

Comparison requires exact normalized core equality; report at most64 field differences and a bounded failure cause. Preserve full identities separately, do not normalize away changed binary/config/host data. An outer ImageVersion-only change can yield a synthetic new-schema profile match only with the same authenticated inner identity; it does not make an old-schema runtime match. Differences in config/tar/rootfs/file-set/file bytes/modes/symlink targets/dependency pins/assets/kernel/CPU flags/counts/engine versions/mount/import/render configuration must reject. Current old C/A records remain rejected by their original gate and are not passed to this new identity parser.

The pure parser checks digest syntax/prefix/length and field binding; it cannot identify the object class behind a same-shaped valid hash. Same-shaped substitutions may parse and only mismatch a different expected field value. Even two identical fabricated records may produce metadata match with native_admission=false. Authentic ZIP/tar/config/diffID object association requires actual artifact/Docker evidence in Task3. Tests must cover duplicate/extra/missing/null/NaN/bool/int/type inputs, image tags and syntactically invalid digest placement, same-shaped hash substitutions with this limited status, shuffled vs changed ordered diffIDs, tampered inventory entries and escapes, forged env-only image assertions, unsupported introspection, secret-bearing serialization, identity-vs-provenance separation, different host profile despite identical image, and legacy-record rejection. These are provider-free fixtures; not retrospective binary proof for C or A.
