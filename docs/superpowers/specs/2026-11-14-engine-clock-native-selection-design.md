## New selection policy

Filesystem mappings must be actual entries of the verified immutable image
manifest, or reviewed checkout source paths. Resolve in-container aliases; reject
deleted image/source files and unknown filesystem mappings. Runtime data mappings
are separately recorded only for exact managed config exclusions, owned /tmp,
private /dev/shm and registered /work/cache/case_00; they MUST be non-executable.
No arbitrary runtime .so/module may become an installed file.

Kernel pseudo regions (heap/stack/vdso/vvar/named anonymous), anonymous memory,
memfd objects, exact SYSV names and /dev/zero backing are separately recorded as
generated/runtime memory. Anonymous executable memory was already omitted by
old installed-file checks; naming it is not evidence of external library bytes.
These objects carry NO installed hash/binary-equality/source-attribution claim.
Host native mounts/devices/display/LD injection remain prohibited. Reject unknown
file-backed executable mappings. Actual module files must be verified image or
source files; CPython builtin/frozen/no-file origins are separate metadata and
cannot promote an arbitrary runtime Python module.

subprocess/import/GL action, and reject malformed, oversized or unknown data.

from bound original manifest/source, writes normalized categories/rejections and
