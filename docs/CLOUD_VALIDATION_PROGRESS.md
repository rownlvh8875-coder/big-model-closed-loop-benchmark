## 여기서 실제로 완료한 영상 재구성

source54e2510 / 원래 실행44176109300의 보존 아카이브5개를 해시·크기·API 실행 원본에 대조했습니다. 새로 렌더링하거나 모델을 실행하지 않았습니다.

- 실제 source RGB964×604 **16장**, 보정 RGB512×256 **16장**의 해시·워프·커버리지·역할·자세를 검증했습니다.
- 원래 `camera_pair_to_model`과 독립적인 I420 여섯 평면 배열 계산이 정확히 일치했습니다. 입력은 uint8 `[2,6,128,256]`이며 첫 차원은 road/wide 두 카메라입니다.
- 두 seed × 두 S 방향에서, 첫 자세의 source/canvas/I420 해시가 **원래 두 모델 실행의 첫 입력과8/8 일치**했습니다. 실제 모델 보고서의 첫 프레임과 추론 감사 행도 대조했습니다.
- 두 번째 자세는 도로 중심을 따라2m 전진한 양성 대조입니다. 모델의 두 번째 시간 스텝으로 사용하거나 인증하지 않았습니다.

## 여기서 수정하고 확인하는 Windows 실행기

기존 Windows full-S/CARLA 실행기도 가상환경의 redirector를 실제 작업 프로세스로 오인했습니다. CPython 방식의 기본 인터프리터 실행과 `__PYVENV_LAUNCHER__`를 공유 helper로 통일했습니다. 카메라 전용 실행기도 같은 helper를 사용하되 기존 cohort 검사와 과학적 카메라 경로는 유지합니다.

worker는 부모가 자신의 실제 PID·nonce·지정 사례를 기록한 뒤에만 native/모델/서버 코드를 시작합니다. 시작 도중 인터럽트는 실행 실패로 단정하지 않고 미확인으로 남기며, 미확인 상태에서 서버를 복구하거나 다른 작업을 시작하지 않습니다. 기존 모델 RAM8GiB 기준·실행 상한·CARLA 전용 서버/복원 조건은 유지합니다.

새 읽기 전용 진단은 **실제 두 worker 진입점**을 표준 라이브러리만 사용하는 모드로 실행합니다. Linux Cloud에서 실행했고, Windows CI는 패키지가 없는 새 가상환경에서도 실행해 PID/부모/가상환경 유지 여부를 확인합니다.

```powershell
python -I -B scripts\run_laptop_validation.py --mode process-check --out output\process-check-01
```

`PROCESS_CHECK_PASS`는 프로세스 소유권 진단 결과입니다. 카메라·모델·CARLA 서버를 실행하지 않으며 full-S/하드웨어/물리광학 검증을 통과시키지 않습니다. 새 출력 폴더만 사용하고 기존 자료를 덮어쓰지 않습니다.

## 실제 장비·자료가 필요한 항목

이 관리형 Cloud에서는 GPU 장치가 관찰되지 않았습니다. **노트북 RTX의 원래 모델 카메라 실행·MSAA**를 인증하려면 그 GPU의 결과가 필요합니다. 이미 끝난 source92fc0b4의8×8 GPU/MSAA PASS를 다시 실행할 필요는 없습니다. Linux 저장 영상의 재검증을 Windows 장치 통과로 바꾸지도 않습니다.

실제 카메라의 물리 보정에는 측정 영상·보정값·독립 자세 자료가 필요하고, CARLA 실제 교차 검증에는 전용 서버가 필요합니다. 현재 그 자료/서버는 제공되지 않았습니다. 별도 비공개 클라우드 full-S 작업은 결과를 관찰할 수 없어 중복 실행하지 않았습니다. 모델 카메라 전체·물리광학·CARLA·7단계 전체 완료는 여전히 미인증입니다. 환경 게시/main 병합은 하지 않았습니다.
