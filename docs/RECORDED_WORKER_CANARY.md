and image. The managed selected host uses CPU receipt readers and unit fixtures.
The separate private official-model job remains unknown and is not duplicated.

The new parent launches the existing Xvfb ownership machinery, acknowledges its
actual child PID and binds a fresh nonce, case, source, activation and run ID.
Admission and the full runnable source map are checked before native imports.
The existing child-reap-before-display-stop path and container cleanup remain.

The observed worker shares the original recorded-body lifecycle and error
handling. The explicit camera-only path makes two actual camera captures, four
sequential road/wide sensor perceives. Startup renders are outside those counts.
It never constructs a graph/session, opens weights or mounts model dependencies.
An audit hook denies ONNX/ORT file opens and ORT imports before SDK bootstrap.

Its two policy audits are not official inferences or a real graph-feed receipt.

and model SHA fields retain their original schema: in CAMERA_ONLY_NO_GRAPH they
mean fixture audit counts, packed camera input digest and spec metadata. The
outer receipts label that scope and record official counts as zero. A real-mode
receiver rejects these fixture receipts. Actual raw camera pixels remain genuine.

An independent approval branch `approval/recorded-worker-canary-20261118-01`

After owned container removal, the runner uses scoped GNU chown with
`--no-dereference --from=65534:65534` for its fresh native directory. Permissions
are not broadened. This makes UID65534 private recordings readable for both
positive and failed-run evidence verification/upload. Hosted Linux tests use an
actual different UID to verify this boundary; the managed host does not use sudo.

The immutable archive reader bounds ordinary ZIP central-directory count and
bytes before parsing entries; it accepts only stored/deflated regular files,
checks raw names before OS normalization (including case aliases/device names),
validates exact local/central/descriptors/CRC and deflate EOF, and atomically
publishes a temporary extraction only after all members succeed. ZIP64 archives
are unnecessary under these caps and are rejected.
